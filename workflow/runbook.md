# 週次実行手順（ランブック）

毎週1回、この手順を最初から最後まで実行する。
定期実行された新しいセッションは会話履歴を持たないため、**この文書だけを読めば
実行できる**ように書いてある。

## 手順0：ネットワーク到達性の確認と、許可ドメインの育成

### 前提の確認（最初に必ず行う）

```bash
curl -sS -o /dev/null -w "%{http_code}\n" --max-time 15 https://www.jgrants-portal.go.jp/
```

`000` が返る場合、クラウド環境のネットワークアクセスが `Trusted` のままで、
公的機関のサイトが全て遮断されている。この状態では公募要領を読めないため、
**WebSearch だけで判定できる範囲に留め、レポート冒頭にその旨を明記する。**

解消するには、claude.ai/code の環境セレクタ（メッセージ入力欄の上の雲アイコン）から
ネットワークアクセスを `Custom` にし、`workflow/sources.yaml` の
`network_allowlist` を「許可されたドメイン」に登録する。
「一般的なパッケージマネージャーのデフォルトリストも含める」のチェックは必ずオンにする。

### 遮断に遭遇したら記録する（重要）

公的機関のドメインは統一されていない（`sources.yaml` の `domain_survey` を参照）。
許可リストは完璧にはならないので、**巡回中に `EGRESS_BLOCKED` に遭遇したら、
そのドメインを必ず記録し、レポート末尾の「追加すべき許可ドメイン」に列挙する。**

ドメインの存在確認はHTTPが通らなくてもDNSで可能：

```bash
getent hosts www.example.lg.jp && echo 実在 || echo 不明
```

この積み重ねで許可リストを育てる。放置すると、その発注機関の案件は永久に拾えない。

## 巡回密度の季節調整

この分野の公募には強い季節性がある（2026-08-26の初回巡回で確認）。

| 時期 | 状況 | 巡回の密度 |
|---|---|---|
| **12月〜6月** | 翌年度案件の公告・締切が集中する繁忙期。取り逃すと1年待ち | **週次＋tier_a は毎回直接確認** |
| 7月〜10月 | 端境期。補正予算関連の補助金が散発的に出る | 週次。WebSearch中心で可 |
| 11月 | 翌年度予算の内示を受けて公告が再開し始める | 週次。tier_a の確認を再開 |

**特に2027年3月中旬〜4月上旬は最優先。** 伝統的工芸品産業振興協会の
「海外におけるテストマーケティング業務」「海外における実演・ワークショップ業務」
（いずれも企画提案募集）が公告される時期で、御社の主力事業と最も一致する案件。
令和8年度は4月1日公告・5月15日締切だった。

## 手順2.5：過年度アーカイブの探索【最重要・2026-08-26 追加】

**この手順を欠いたことが、初回サーチ最大の欠陥だった。**

### なぜ必要か

発注機関のサイトは「現在募集中の案件」しか新着に出さない。しかし、

1. **翌年度事業の委託先は前年度中に決まる。** 東京都中小企業振興公社の場合、
   令和8年度案件は令和8年1〜3月に集中公告されていた。「今年度の新着」を見ても
   翌年度案件は出てこない。
2. **終了案件こそがカレンダーの材料。** いつ公告され、いつ締め切られたかは
   過年度アーカイブにしか残っていない。

実例：御社が令和7年度に4,098万円で受注した「東京手仕事 MAISON & OBJET 出展及び
ポップアップストア運営業務」の後継案件（令和8年度）は、**2026年2月24日公告・
3月3日締切**で既に終了していた。新着だけを見ていたため、初回サーチでは
この案件の存在自体を検出できなかった。

### やること

`workflow/sources.yaml` の各組織について、**「過年度」「終了した公募」「入札結果」
「契約情報」のアーカイブページを探し、最低3年分を遡って読む。**
リンク文言の手がかりは以下。

```
過年度 / 過去の公募 / 終了した公募 / 公募情報一覧（終了分） / 入札結果 /
契約情報 / 落札結果 / 実施済み / アーカイブ / 年度別
```

読み取るのは案件名だけでなく、**公告日と締切日**。これがカレンダーの精度を決める。
複数年度に同名・同種の案件が現れたら、それは定例案件であり `calendar.yaml` に登録する。

### 確認済みのアーカイブ経路

| 組織 | アーカイブURL |
|---|---|
| 東京都中小企業振興公社 | `https://www.tokyo-kosha.or.jp/kosha/keiyaku/end/index.html`（令和2〜7年度） |
| 中小機構 | `https://www.smrj.go.jp/procurement/solicitation/expiry/index.html` |
| 伝統的工芸品産業振興協会 | `https://kyokai.kougeihin.jp/association_cat/公募公告/`（過去分も同一ページに残る） |
| 調達ポータル | `https://www.p-portal.go.jp/pps-web-biz/UAB02/OAB0201`（落札実績情報の一覧） |

### 事前登録が必要なポータル

| ポータル | 対象 | 備考 |
|---|---|---|
| **ビジネスチャンス・ナビ** `chancenavi.jp` | 東京都・公社の調達 | **希望申出はここでのみ受付。事業者登録が必須。** 公告から締切まで7〜10日しかないため、未登録だと物理的に間に合わない |
| 調達ポータル `p-portal.go.jp` | 国の調達 | 全省庁統一資格と連動 |

## 手順3.5：公募カレンダーの照合（「まだ出ていない案件」の先回り）

`workflow/calendar.yaml` を開き、**`watch_from` が当日から30日以内に入っている項目**を
すべて洗い出す。それぞれについて発注機関のサイトを直接確認し、

- **公告が出ていた** → 台帳へ登録し、`observed:` に実績を追記する
- **まだ出ていない** → レポートの「間もなく公告される見込み」欄に残日数とともに記載する
- **予測が外れた**（時期がずれた・制度が終了した） → `confidence` を下げるか項目を削除し、
  理由をコメントで残す

これを続けることで予測精度が上がる。**カレンダーは巡回のたびに育てる資産である。**

### GREEN×EXPO 2027 は毎回全県チェック

`tier_expo2027` は例外扱い。2027年国際園芸博覧会（横浜・2027年3月開幕）への
出展業務委託は、各都道府県・政令市が2026年度中に順次公告する。
**毎回の巡回で「国際園芸博覧会」「GREEN×EXPO」「園芸博」を全県横断で検索すること。**
既に福島・福岡・宮崎で確認済み。未公告の県は今後半年で出す可能性が高い。

## 手順4：判定

見つかった各案件について、`workflow/eligibility.md` の手順を適用する。

1. 足切り判定（500万円未満・締切超過・除外語・地域限定・個人限定）
2. 応募形態の判定（単独／共同／支援側／受託）
3. 全省庁統一資格の要否と間に合うか
4. スコアリング（S/A/B/C）
5. 実績要件を満たせるか

**判定の根拠となる記述は、公募要領の該当箇所を引用して残すこと。**
「応募できます」だけでは生島様が確認できない。

### 締切の扱い

| 締切までの残日数 | 表示 |
|---|---|
| 7日未満 | **【至急】** 準備期間がほぼない。提出可否の即断が必要 |
| 8〜21日 | **【要着手】** 通常の提案書作成期間 |
| 22日以上 | 通常 |

## 手順2.6 分母の維持（2026-08-27 追加）

初回の全量抽出で、母集団は **8,958件／218組織** と確定した。
以後は「新着だけを見る」のではなく、**分母を更新して差分を取る**。

```bash
python3 bin/denom.py            # 218組織を2階層で全量巡回（業種フィルタなし）
python3 bin/rank.py             # 契約案件性ゲート → S/A/B判定
python3 bin/fetch_deadlines.py  # S/A案件の詳細ページから締切を抽出
```

判定は3段のゲートを通す。順序を入れ替えないこと。

1. **契約案件性** — 委託・業務・プロポーザル・企画競争・入札・請負・補助金等を含むか
2. **ノイズ除外** — セミナー／受講者募集／**出展者募集**／指定管理者／工事・清掃・警備
3. **業種適合** — 展示会・海外展開・工芸／地域産品・プロモーション・観光・文化・イベント運営

> ゲート1を省くと、JETROのサービス提供者リンク集のような
> 「案件ですらないもの」がS格に混入する。初回はこれで146件が汚染された。

### 分母から見えた3つの構造的取りこぼし

- **「現在募集中」だけを見ると翌年度事業を全て逃す。**
  GREEN×EXPO 2027 の県出展業務6件は、いずれも会期の前年度に公告されていた。
- **外郭団体の発注密度が突出して高い。**
  組織数は61で全体の28%だが、装飾・設営案件の過半を占める。
  **都道府県本体より外郭団体を優先して巡回する。**
- **巡回間隔が発注の窓より短くない。**
  大分県産業創造機構の案件は参加申込期間が9日間しかなく、週次巡回では取りこぼした。

### 巡回頻度の改定

| 対象 | 頻度 | 理由 |
|---|---|---|
| 外郭団体61組織の入札・公募ページ | **週2回（月・木）** | 参加申込型の窓が7〜10日しかない |
| 都道府県47・市区町村90 | 週1回 | 掲載期間が比較的長い |
| GREEN×EXPO 2027 全県スイープ | **毎月** | 残り40県超が2026年度後半〜2027年前半に公告 |
| 分母の全量再抽出 | 四半期 | 巡回先マスタの陳腐化を検出する |

### 参加申込型は締切が二段ある

公募型プロポーザルの多くは **参加申込 → 企画提案書** の二段構えで、
**先に来るのは参加申込の期限**である。台帳の `締切` には
**早いほうの期限**を入れる。提案書の締切だけを見ていると、
申込を逃した時点で応募資格を失う。

### 「出展企業募集」と「設営等業務の委託」を混同しない

産業支援機関の一覧には両方が並ぶ。

- **設営等業務／装飾委託業務／ブース企画・設営業務** → 当社が受託者として応募する
- **共同出展企業募集／出展者募集／参加発注企業募集** → 出展する企業向け。当社は対象外

京都産業21の一覧80件のうち、当社が応募できるのは装飾等業務だけである。
`bin/rank.py` のノイズ除外に `出展者募集|出展企業募集` を入れてあるのはこのため。
