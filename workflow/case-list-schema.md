# 案件リストの仕様

週次巡回のたびに、レポート（Markdown / アーティファクト）とは**別に**案件リストを作る。

- 実体: `data/cases/cases_YYYYMMDD.xlsx`（配布用）と `.csv`（26項目）
  生成: `python3 workflow/make_case_list.py data/cases/cases_YYYYMMDD.csv`
  **CSV を UTF-8（BOMなし）で渡すと Mac の Excel で文字化けする。**
  生成スクリプトが CSV を BOM 付きに書き直し、Excel も出力する。
- 表示: 同内容を一覧アーティファクトとして公開し、各行からレポートの該当節へリンクする
- `data/ledger.csv`（累積台帳）との違い: 台帳は**通期の履歴**、案件リストは**その回の棚卸し**。
  台帳に既出の案件でも、その回に判定が動いたもの・締切が迫っているものはリストに載せる。

## 二層構成

**一覧（アーティファクト）に出すのは9列だけ。** 列を増やすと一覧の意味がなくなる。
残りはCSVに持ち、詳細はレポート本文へリンクで飛ばす。

| 一覧に出す | 内容 |
|---|---|
| 格付 | S / A / B / C。緊急度は行の左端の色帯で表す |
| 案件名 ＋ 種別 | 種別はタグで小さく添える |
| 発注機関 | |
| 見込み金額 | 金額確度の記号を必ず併記する |
| 締切 ＋ 残日数 | |
| **直近アクション期限** | 締切より前に来る期限。**この列が本リストの要** |
| 応募形態 | |
| 資格 | |
| 判定 ＋ 次アクション | |

「直近アクション期限」を独立させる理由：**実際の分岐点は締切ではないことが多い。**
2026-08-19 の JETRO 日本館運営は、締切が 9/8 でも、入札説明会の参加申込が 8/25 9:00、
全省庁統一資格の等級確認申請が 8/26 17:00 で、そこを逃すと締切前に応募不能が確定する。
締切だけを見ていると取り逃す。

### 緊急度の決め方

残日数は **直近アクション期限**（12）で測る。締切（10）ではない。

ただし **12 に入れてよいのは「公表された期限」だけ**。こちらの判断で置いた推奨日
（「GビズIDは今週中に着手すべき」等）は緊急度の計算に使わない。使うと全件が至急になり、
色分けが意味を失う。推奨日は 12 に「YYYY-MM-DD（推奨）」と書き、残日数は公表期限で測る。

| 残日数 | 緊急度 |
|---|---|
| **7日以下** | 至急 |
| 8〜21日 | 要着手 |
| 22日以上 | 通常 |

`runbook.md` 手順4の表は「7日未満／8〜21日」となっており **7日ちょうどが抜けている**。
本仕様では 7日以下を至急として穴を塞いだ。runbook 側も同じ区切りに揃えること。

**実例（2026-08-19）**: JETRO 日本館運営は締切が 9/8（残20日）だが、入札説明会の参加申込が
8/25 9:00（残6日）で、そこを逃すと締切前に応募不能が確定する。よって緊急度は**至急**、
残日数は**6**。締切だけを見て「要着手」と判定してはいけない。

## 書き方の原則

- **金額を空欄にするときは、必ず金額確度に `－非公開` を入れる。** 空欄＋空欄は「調べていない」と区別がつかない
- 推定値には確度 `△推定` を入れ、レポート本文に推定の根拠を書く
- 判定が `見送り` でも行は消さない。翌年度に同じ公募が出るため、記録として残す
- 一次情報URLは発注元の原典のみ。NJSS等の集約サイトで見つけた案件も、原典を確認してそのURLを書く
### リンクの検証（毎回必須）

```bash
python3 workflow/check_links.py data/cases/cases_YYYYMMDD.csv
```

**HTTP 200 だけで「リンクは生きている」と判断してはいけない。**
2026-08-20 に実際にやらかした失敗：ビジネスチャンス・ナビの案件詳細 URL を
一次情報URLに入れたが、あのページは **POST 専用**で、GET（＝リンクのクリック）では
200 を返しながら本文181文字の空の殻しか返さない。生島様がクリックしても案件に辿り着けなかった。

check_links.py は 200 だけでなく **本文の長さと案件名の出現**まで見る。
FAIL が出たまま配布しない。

既知の制約：
- **ビジネスチャンス・ナビの案件詳細（uab0401〜0404）はクリック可能なURLが存在しない。**
  公社の契約情報一覧へリンクし、`前提条件` 列にナビ案件番号を書いて検索できるようにする。
- 日本語を含むURLはパーセントエンコードして書く（貼り付け事故を防ぐ）。

### 一覧のリンクの張り方

**案件名のリンク先は「発注元の案件ページ」。** レポートではない。
一覧を見ている人が案件名をクリックしたら、案件そのものに行きたいはず。
レポートの解説へは、案件名の隣に小さく「解説 →」を別に置く。

予測案件は案件ページがまだ存在しないので、監視先の一覧ページを指す。

- **予定価格が非公開でも諦めない。**過年度の落札金額から規模を推定する。
  JETRO・国際交流基金・経済産業省は落札金額を公表している（`sources.yaml` の `award_amounts`）。
  東京都中小企業振興公社は公表していないので、その旨を金額の根拠に明記する。
  推定できた場合は `△推定` とし、根拠に実測値を書く
- **予測案件は根拠つきでのみ載せる。**「例年出ている気がする」は載せない。根拠は過年度の公告一覧から取る：
  東京都中小企業振興公社 https://www.tokyo-kosha.or.jp/kosha/keiyaku/end/index.html ／
  伝産協会 公募公告のページ送り ／ JETRO 調達情報のカテゴリ別
- **東京都中小企業振興公社の案件は、必ずビジネスチャンス・ナビ側の詳細も見る。**
  契約方法（希望制指名競争入札／総合評価方式入札）・案件受付期間・入札資格の有無は
  公社サイトの一覧には出ず、ナビの詳細ページにしかない。`workflow/fetch_chancenavi.py`
  でログイン不要で取得できる。「委託」と一括りにすると、希望申請と入札書提出を取り違える
