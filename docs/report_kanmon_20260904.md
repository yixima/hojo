## 2. なぜ起きたか — 7つの見地からの検証

### (1) 構文解析の見地 ── 行構造を壊してから、距離で復元しようとした

旧 `bin/audit_gates.py` は本文をこう潰していた。

```python
text = re.sub(r'<[^>]+>', ' ', raw.decode('utf-8','ignore'))
```

**この1行で `</tr>` が空白になり、表の行境界が消えた。**
そのうえで、日付ごとに **後方90字・前方25字** の窓を切ってラベルを探していた。

実測した窓（`&nbsp;` を含む生の文字列）：

```
9月 1日 の窓(-90,+25): 「…質問書への回答 令和8年9月 1日（火）正午まで 参加申込書の提出」
                                                        ↑ 「期限」が25字の外で切れた
9月 4日 の窓(-90,+25): 「…令和8年9月 1日（火）正午まで 参加申込書の提出期限 令和8年9月 4日（金）正午まで 企画提案書の提出」
                                    ↑ 前の行のラベルが窓に入っている
```

判定条件は「窓の中に 締切／期限／必着 があること」だった。したがって、

- **9/1 は「期限」が25字の外にあったため、条件を満たさず捨てられた。**
- **9/4 は後方窓に前の行の「参加申込書の提出期限」が入ったため、「参加表明」と判定された。**

**日本語のスケジュール表は「日付 → ラベル」の順に書かれる。**
にもかかわらず窓は後方に3.6倍広かった。**窓の向きが、言語の語順と逆だった。**
結果として、**表のすべての日付が1行前のラベルを継承する。**

これは福島県に固有の現象ではない。**平文に潰された表すべてに一様に起こる系統誤差である。**

### (2) フェイルセーフの見地 ── 判定不能が「一致」に化けた

旧実装は、ラベルが読めなかった日付を **`continue` で捨てていた**。

```python
if not re.search(r'締切|締め切り|期限|必着', win): continue
```

捨てた結果どうなるか。真の関門 9/1 が候補から消え、残った 9/4 が「最早の関門」になり、
台帳の 9/4 と **一致した**。監査は「ずれ」を出さず、**1行も出力しないまま通過した。**

**「不一致の証拠が無い」が「一致」として報告された。**
これはフェイルセーフの向きが逆である。**読めなかったときの既定は「未検証」でなければならない。**
沈黙を合格と読むのは、検査として成立していない。

### (3) データモデルの見地 ── 1つの列に2種類の期限を押し込んだ

台帳の `締切` 列は1つしかなく、**「それが何の締切か」を持てなかった。**
種別は「状態」欄の日本語の中にしか無い。したがって、

- 台帳だけを見ても、参加申込と提案書のどちらを入れたのか判別できない
- 機械が突き合わせようにも、比較すべき対象が定義されていない
- **人が書き間違えても、書き間違えたことがどこにも現れない**

`workflow/runbook.md`（および週次巡回の指示文）には、私が自分でこう書いてある。

> **参加表明の二段構えに注意。**確認できた案件はすべて「参加表明 → 提案書」の二段。
> 先に来るのは参加表明で、これを逃すと提案書を出せない。**台帳の締切欄には早いほうを入れる。**

**規則は書いてあった。規則を守ったかどうかを表現する場所が、台帳に無かった。**

### (4) 検査工学の見地 ── 検査スクリプトにテストが1件も無かった

`bin/audit_gates.py` は 2026-08-27 に作られてから一度も回帰テストを持たなかった。
**「検査するもの」が壊れていることを検査するものが無い。**
既知の正解（福島の9/1、おまつり歳時記の9/7）を固定資産として持っていれば、
窓の向きの誤りは最初の1回で露見していた。

### (5) 網羅性の見地 ── 検査対象が全体の41%しかなかった

旧実装の対象は `格付 in ('S','A')` の110件（台帳268件の41%）だった。
**B・C・D等級の行は一度も検査されていない。**
今回もう1件見つかった宮崎県の案件は **格付B** である。**旧実装では永久に見つからなかった。**

### (6) ヒューマンファクターの見地 ── 隣接行同型錯誤と、手がかりの自己消去

一次資料の表は、こうなっている。

```
令和８年９月 １日（火）正午まで  参加申込書の提出期限
令和８年９月 ４日（金）正午まで  企画提案書の提出期限
```

**2行が同じ形をしている。**「令和８年９月 _日（_）正午まで ___書の提出期限」。
差異は日付と2文字（参加申込／企画提案）だけである。
**書式が同型で隣接する行は、視線が1行ずれても違和感が出ない。**転記誤りの典型的な発生条件である。

さらに悪いことに、私は状態欄に **「参加申込9/4正午必着」** と書いた。
**種別と日付を、自分の言葉で1つの括弧に閉じてしまった。**
一次資料に当たり直さないかぎり、この記述は内部矛盾を起こさない。
**取り違えに気づくための手がかりを、自分の手で消していた。**

### (7) 工程管理の見地 ── 「人が読む」工程に、実施の記録が無い

`audit_gates.py` の docstring には私自身がこう書いている。

> **候補を出すところまでが機械の仕事で、確定は一次資料を人が読んで行う。**

**正しい。だが「読んだ」ことを記録する欄が、どこにも無かった。**
福島県について、募集要領PDFを開いてスケジュール表を読んだ形跡は残っていない。
読んだのか読まなかったのかを、後から誰も判定できない。
**工程を定義しながら、その工程の完了条件を定義していなかった。**
