## 2. 原因（影響の大きい順）

### 原因1：Drive コネクタの保存が1本1〜9分かかる【確認済】
- 同じ束で送った2本が9分3秒ずれて完了した。呼び出しは直列に処理され、1本に数分かかる。
- 本文を呼び出しに同梱する方式（`create_file`）しかなく、ファイルパス指定の送信ができない。
- 私の側で悪化させた点：**固定名と日付版の2本を毎回送った**。改名で3本目も発生した。
- 推定寄与：約15分（1＋9＋5分）。3本目の開始時刻は正確に記録できていないため、5分は【未確認・推測】。

### 原因2：同じ文書を何度も生成した【確認済（文字数）／【未確認・推測】（所要時間）】
| 出力 | 文字数 |
|---|---|
| 引き継ぎ v1 本文（ヒアドキュメント） | 18,792 |
| 同 base64 をツール呼び出しに転記 ×2 | 50,112 |
| 改名版 本文 | 15,575 |
| 同 base64 を転記 ×1 | 20,768 |
| **合計（私が生成した文字）** | **約105,000** |
- 加えて `cat` と `base64` の出力を自分の文脈に読み戻した（約86,000字）。
- base64 は圧縮が効かない文字列で、言語モデルの生成速度が最も遅い種類の出力である。**バイト一致を保証したくて選んだ方式が、時間を最も消費した。**
- 推定寄与：10〜15分【未確認・推測】。生成速度は実測できない。

### 原因3：時刻を手入力して2度書き直した【確認済】
- `today.sh` が 17:40 と出ているのに 17:39 と書いた。18:01 と出ているのに 18:08 と書いた。
- `CLAUDE.md`「その場で取得した値のみを使う」に違反。**手で写した時点で間違えている。**
- 直すたびに コミット→プッシュ→base64 再生成 が走った。推定寄与：3〜5分＋原因2の一部。

### 原因4：冒頭で読み過ぎた【確認済】

- 加えて `CLAUDE.md`・企画案281行・会社プロファイル・マニュアル本体（32KB）を読んだ。マニュアルと `CLAUDE.md` は必須、他は必要になってからでよかった。
- 推定寄与：5〜10分【未確認・推測】。

### 原因5：長い処理の前に一言も出さなかった【確認済】
- Drive 保存の前に「数分かかる」と出していない。生島様には停止と区別がつかない。
- マニュアル §5.5「走っていないのに実行中と書かない」の裏返し：**走っているなら、走っていると先に書く。**

### 原因ではなかったもの

- 改名の指示そのもの：作業のやり直しは必要だったが、遅延の主因ではない。主因は上の1〜3。
