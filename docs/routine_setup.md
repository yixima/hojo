# 週次巡回が動かない原因と、直しかた（2026-09-16）

## 何が起きているか

**週次巡回の Routine は、発火のたびに「新しいセッション」を作る。**
その新しいセッションには、**リポジトリもコネクタも付いていない。**

| 日付 | 症状 | 実際の原因 |
|---|---|---|
| 2026-09-07 | **git push が「リポジトリ未認可」で拒否**。新規4件が GitHub に反映されなかった | 新セッションに `yixima/hojo` が付いていない |
| 2026-09-07 | **Gmail と Google Drive が使えず**、レポートを送れなかった | 新セッションにコネクタが付いていない |
| 2026-09-14 | 発火したが、台帳にもボードにも成果が残らなかった | 同上（作業はしたが保存先が無い） |

**アカウント側の問題ではない。**2026-09-16 に実測：
Gmail・Google Calendar・Google Drive はいずれも `connected: true`、
このセッションでは `enabledInChat: true` で**使える状態にある**。
足りないのは **Routine が作る新セッションへの引き継ぎ**である。

## なぜ私（アシスタント）側で直せないか

`update_trigger` で変更できるのは **名前・スケジュール・有効/無効・モデル・プロンプト**だけである。
**リポジトリとコネクタは変更できない。**
`create_trigger` にはコネクタの指定はあるが、**リポジトリを付ける項目が無い。**

したがって選択肢は2つ。

---

## 案A（推奨）── 週次巡回を「このセッション」に結び付ける

新しいセッションを作らず、**リポジトリもコネクタも揃っている今のセッション**へ発火させる。

- 長所：**リポジトリもコネクタもそのまま使える。**私の側だけで設定でき、生島様の操作は不要
- 短所：巡回の作業が今のセッションの中で走るため、**セッションが重くなる**
  （引き継ぎの目安は文脈使用率50%。2026-09-16 時点で約33%）

**ご指示をいただければ、この場で切り替えます。**

---

## 案B ── 週次巡回の Routine を作り直す（生島様の操作が要ります）

claude.ai/code の画面から作り直すと、**リポジトリを付けた新セッション**が毎回作られます。

### 手順

1. ブラウザで **https://claude.ai/code** を開く
2. 左側のメニューから **Routines**（定期実行）を開く
3. **「公募案件 週次巡回（ジャパンプロモーション）」** を選ぶ
4. **削除**する（※先に手順5〜8で新しいものを作ってからでも構いません）
5. **New Routine**（新規作成）を押す
6. 次を設定する
   - **Repository／Source**：`yixima/hojo` を選ぶ
     **← ここが今まで空だった。最重要**
   - **Branch**：`claude/public-bid-search-workflow-uzj3te`
   - **Environment**：`公募案件リサーチ`（または `Default`）
   - **Schedule**：毎週月曜 08:00（内部では UTC 日曜 23:00 ＝ `0 23 * * 0`）
   - **Connectors**：**Gmail** と **Google Drive** の両方にチェックを入れる
     **← ここも今まで空だった**
   - **Prompt**：いまの Routine の本文をそのまま貼る（私が全文をお渡しできます）
7. 保存する
8. **「今すぐ実行」**があれば1回押して、
   - リポジトリに push できるか
   - メールが届くか
   の2点を確かめる

### 確認のしかた

翌朝の私の報告に、次の2行が出れば成功です。

- 「週次巡回が台帳に N件を追記した（commit ○○）」
- 「iximay@gmail.com へレポートを送信した」

**どちらも出なければ、まだ直っていません。**黙って成功したことにしません。
