## 1. `uzj3te` に無い唯一の機能：落札実績オープンデータ

**`workflow/awards_pportal.py`** — これだけは `uzj3te` に該当物が無い（実測：
`bin/` 配下に `successful_bid_record_info` への言及なし）。

調達ポータルが国の調達の落札実績を**全件CSV（zip）で配っている**ことを見つけた。
R5〜R8の4年度・約11.6万行。案件番号・件名・落札日・落札金額・落札者・法人番号が
1行ずつ入っている。取得先は次の1本。

    https://api.p-portal.go.jp/pps-web-biz/UAB03/OAB0301?fileversion=v001&filename=successful_bid_record_info_all_{年}.zip

`--match` を付けると、拾った案件の件名を正規化（年度表記と案件番号を落とす）して
過年度実績に突き合わせる。実測：166件中79件に直近の落札金額と落札者が付いた。
**「仕様書から積算」に頼らずに済む案件がかなりある。**

包含一致には長さ比0.7の下限が入っている。外すと無関係の案件が短い件名を含むだけで
前年実績として付く。**金額欄に嘘が入るのが一番まずい。**

限界：**国の機関のGEPS経由の調達だけ。** 都道府県・市区町村・外郭団体は入らない。

## 4. `uzj3te` と重複する道具（採用しないこと）

本枝の下記は `uzj3te` 側が先に、より良く作っている。**参考として残すだけ。**

| 本枝 | `uzj3te` の該当物 | 判定 |
|---|---|---|
| `workflow/sweep_pportal.py` | `bin/pportal.py` | `uzj3te` が正。あちらは実ブラウザで操作する |
| `workflow/sweep_tokyo.py` | `bin/tokyo_procurement.py` | `uzj3te` が正。8/28 に到達手順を確立済み |
| `workflow/sweep.py` `find_procurement.py` `harvest_*.py` | `bin/denom.py` `bin/sweep_channels.py` | `uzj3te` が正。母集団を制度台帳・チャネル台帳で定義しており、本枝の「見つけたもので定義する」より正しい |

ただし**実装中に潰した落とし穴は、あちらにも効く**ので記録しておく。

- 調達ポータルの類義語区分02は「工芸」を「作物」に展開する。01（含まない）を使い、
  広く取りたいときは検索語のほうを増やす
- 調達ポータルは1ページ50件が上限。ページ送りが無いと103件中50件しか取れないのに
  **件数表示は103のまま**で、取りこぼしに気づけない
- 調達ポータルには**調達案件番号が「‐」の案件がある**。2027年国際園芸博覧会の
  政府出展などがこの形。数字判定で弾くと一番欲しい案件だけが消える
- 東京都電子調達の必須項目は**隠しフィールドの `consgoods`**。画面上のラジオ
  （`constConsgoods`／`itemConsgoods`）だけ送ると「検索条件なし コード6」で弾かれる
- 東京都電子調達の一覧は**500件で頭打ち**なのに、画面は総件数621件と出し続ける。
  契約方法（一般競争／希望制指名／随意）で3分割すると上限に届かない
- 東京都電子調達は **Windows-31J**。UTF-8で読むと件名が全部化ける
