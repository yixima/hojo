### 10-6. 台帳を書き換えるときの必須ガード

**台帳を機械的に書き換える処理は危険。過去に2度壊してgitから復元した。**
**必ず行数を assert してから書く。締切が確定している行は絶対に落とさない。**

```python
import csv
p = 'data/ledger.csv'
rows = list(csv.reader(open(p, encoding='utf-8')))
hdr = rows[0]
i_name = hdr.index('案件名'); i_state = hdr.index('状態')
n = 0
for r in rows[1:]:
    if 'おまつり歳時記' in r[i_name]:
        r[i_state] = '（新しい状態）'
        n += 1
assert n == 1, n                     # 想定件数と一致するか
assert len(rows) == 262, len(rows)   # 行数が変わっていないか
csv.writer(open(p, 'w', encoding='utf-8', newline='')).writerows(rows)
```

### 10-7. 東京都電子調達システム（別件だが、週次巡回で使う）

```bash
python3 bin/tokyo_procurement.py            # 当社に該当する種目だけ
python3 bin/tokyo_procurement.py --all      # 全件
python3 bin/tokyo_bid_results.py <キーワード>  # 過去の落札金額と全入札者
```

**要点3つ**（`bin/tokyo_procurement.py` の docstring に詳しい）
- 文字コードは **Windows-31J（CP932）**。UTF-8 で投げると0件になる
- **`allBureauFlag=1` が必須。**これがないと「該当なし」しか返らない
- **件名で絞ってはいけない。**「催事関係業務」は件名ではなく**営業種目の欄**にある。
  全件を取ってから営業種目で絞る
- **「入札結果一覧」（page=3/act=14）はシステムエラーを返す。
  使えるのは「入札（見積）経過情報」（page=3/act=4）**

全件走査は5〜6分かかる。`run_in_background: true` で実行し、
`until grep -q 'DONE' <ログ>; do sleep 15; done` で待つ。
